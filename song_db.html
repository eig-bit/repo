本頁為單一 HTML 檔的離線應用；資料 100% 存本機，僅在「試聽」與「線上搜尋」時連外查詢 Apple。以下為各功能完整技術細節。

01 ▸ 線上搜尋與試聽 ── iTunes Search API（Apple 官方 · 免 API Key）

兩種搜尋，各司其職：工具列搜尋框只過濾本機 IndexedDB 曲庫（即時、離線可用）；「線上搜尋」才會連 iTunes。當本機查無結果時，按 Enter 或點空狀態按鈕即可帶著關鍵字直接線上搜尋。

「線上搜尋」呼叫 Apple 官方 API：

GET https://itunes.apple.com/search?term=…&media=music&entity=song&limit=25&country=…

免註冊、免 API Key，官方建議頻率約 20 請求/分鐘（本頁僅在使用者主動操作時請求）。結果可試聽官方授權的 30 秒片段（AAC/HTTPS），由 HTML5 <audio> 串流播放。

環節實作方式
傳輸策略先以 fetch 直連（API 支援 CORS，含 7 秒逾時）；失敗自動降級 JSONP（callback 參數 + 動態 script 標籤），雙保險
線上搜尋每頁 25 筆、「載入更多」以 offset 翻頁並依 trackId 去重；可切換商店（US/TW/HK/JP/GB）提升各地區歌曲命中率；一鍵加入曲庫自動帶入歌名／演出者／專輯／年份／曲風／音源與專輯封面 URL，並依「歌名+演出者」常規化判斷是否已在曲庫
卡片試聽配對以「歌名＋演出者」搜尋後對每筆結果計分：曲名完全相符 +4、部分 +2；演出者完全 +3、部分 +1.5；取最高分且含 previewUrl 者；US 查無自動改查 TW
結果快取配對成功後把 previewUrl 存入 IndexedDB，之後播放免再查詢；音源失效（連結過期）自動清快取並重新配對一次
自訂音源編輯表單可填入任何直連音訊網址，或「解除配對」強制下次重新搜尋
自動播放解鎖iOS Safari 要求 play() 在手勢內同步呼叫：點擊時先以 0 秒靜音 WAV 解鎖 audio 元件，之後網路配對完成再播放不會被擋
Media Session鎖定畫面／通知列顯示曲名、演出者與封面（iTunes 專輯圖優先、無則用像素封面），可遙控播放／暫停
連續播放30 秒結束自動播放清單下一首（依目前排序／過濾結果）

隱私與離線：資料庫完全離線；只有試聽／線上搜尋時向 Apple 發出請求。無網路時這兩項不可用，其餘功能照常。30 秒片段長度與內容由 Apple 提供，完整播放請支持正版。

02 ▸ 資料儲存 ── IndexedDB

所有歌曲資料儲存在瀏覽器 IndexedDB：資料庫名稱 pixelTuneVault、物件倉庫 songs、主鍵 keyPath 為 id。IndexedDB 是非同步、交易制的 NoSQL 儲存，容量遠大於 localStorage。載入時 getAll() 一次進記憶體，搜尋、排序、過濾全在記憶體完成；任何寫入（新增／編輯／刪除／收藏／匯入／試聽快取）都同步寫回。介面偏好只用 localStorage 存開關，與歌曲資料分離。

欄位型別說明
idstringUUID，主鍵
titlestring歌名（必填）
artist / album / genre / keySigstring演出者／專輯／曲風／調性
year / bpmnumber年份／速度
notesstring備註
previewUrlstring|null試聽音源（iTunes 快取或自訂網址）
previewSrc'itunes'|'custom'|null音源類型
artUrlstring|nulliTunes 專輯封面 URL（Media Session 用；卡片仍用像素封面）
seednumber像素封面生成種子
favoriteboolean收藏標記
createdAt / updatedAtnumber建立／更新時間戳

每張卡片的像素封面由 seed 決定性生成：12×12 網格左右鏡射隨機填色（NES 風調色板），同一首歌永遠同一張封面，匯出分享後亦然。

03 ▸ 持久化 ── navigator.storage.persist()

瀏覽器在儲存空間吃緊時可能自動清除未被標記的來源資料──這是 IndexedDB 資料「憑空消失」的最常見原因。呼叫 navigator.storage.persist() 可將本站標記為持久儲存，納入不被自動清除的保護；Chromium 會依站點重要性（互動頻率、是否安裝成 PWA）決定是否核准。本頁載入時會自動申請一次，也可隨時手動申請，並以 navigator.storage.estimate() 即時顯示用量與配額。把本站「安裝到主畫面」會大幅提升核准機率。

04 ▸ 匯入 / 匯出 ── JSON

匯出：把全部曲目（含音源快取、封面 URL、seed 與時間戳）包成 {app:"pixelTuneVault", version:1, exportedAt, songs:[…]}，以 Blob + URL.createObjectURL 觸發下載，檔名含日期。匯入支援兩種模式：

· 合併：以 id 為鍵 upsert──既有 id 覆蓋更新、新 id 新增
· 取代：先清空 songs 倉庫，再整批寫入

匯入時會做格式驗證與欄位正規化（含 URL 白名單檢查），缺少 id 的項目會補上新 UUID；支援點選或拖放 .json 檔。

05 ▸ 加入主畫面 ── A2HS

本頁是單一 HTML 檔，因此 Web App Manifest 是執行時動態組出的：先用 canvas 繪製像素圖示轉成 PNG data URI，再與 manifest JSON 一起編成 data: URI 注入 <link rel="manifest">，並同步設定 favicon 與 apple-touch-icon。瀏覽器發出 beforeinstallprompt 事件時，橫幅上的 INSTALL 按鈕會呼叫 prompt() 觸發原生安裝；不支援的環境（如 iOS Safari）會改為顯示手動步驟（分享 → 加入主畫面）。安裝狀態以 display-mode: standalone 偵測，安裝後不再打擾。

注意：原生安裝提示需要 https 環境──部署到 GitHub Pages 後即可完整生效。

06 ▸ 除錯防護、響應式與無障礙

錯誤可視化：頁面掛載 window 的 error 與 unhandledrejection 監聽器──任何未捕捉的腳本錯誤或 Promise 拒絕，都會以右上角紅色 toast 顯示（資源載入失敗如封面圖 404 則靜默略過），方便在 GitHub Pages 上第一時間發現問題；按 F12 開啟 Console 亦可看到完整堆疊。所有事件綁集中在腳本執行期完成，初始化（DB 開啟、偏好還原）非同步進行且個別以 try/catch 防護，單一環節失敗不會拖垮其他按鈕。

響應式：版面以 CSS Grid auto-fill 自動斷行，手機 1 欄、平板 2 欄、桌面 3 欄以上；播放列在窄螢幕收合均衡器並預留 iOS 安全區（env(safe-area-inset-bottom)）。像素外框與按鈕立體感全部由 box-shadow 疊加構成、掃描線為 2px 重複紋理覆蓋層；動畫尊重 prefers-reduced-motion；表單聚焦有明顯 outline、操作按鈕均有 aria-label；輸入框字級在行動裝置固定 16px 防 iOS 聚焦縮放。

07 ▸ 部署到 GitHub Pages

① 將本檔存成 index.html，上傳到 GitHub repository。
② 進入 Repo Settings → Pages，Source 選 main branch / root，按 Save。
③ 數分鐘後即可透過 https://<帳號>.github.io/<repo>/ 開啟。https 環境下，A2HS 安裝提示、Storage Persistence 與 iTunes API（要求安全環境的瀏覽器政策）都會完整運作。更新檔案後若畫面未變，請以 Ctrl+F5（Mac：Cmd+Shift+R）強制重新載入，避開舊快取。
